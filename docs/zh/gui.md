# GUI 公用状态

## 界面样式

界面使用浅色中性背景与绿色强调色，侧栏集中展示导航，新建会话作为主要操作；当前会话和收件箱入口提供选中状态。会话正文、输入区和弹窗通过间距、边框及轻阴影区分层次，按钮与表单保持统一圆角和清晰的键盘焦点。

会话列表按[会话列表规则](sessions.md#会话列表)排序并滚动分页，使用纯文字单行标题，长标题省略并通过悬停提示显示完整内容。当前会话以白色背景、绿色侧边标记和加粗标题区分；查看收件箱时不标记会话为当前页。“更多”按钮在桌面悬停、键盘聚焦或当前会话中显示，窄屏和触屏设备始终显示；操作菜单与行内重命名保持统一圆角和间距。

会话详情以正文阅读为主：用户消息使用右侧浅色气泡，助手回复保持开放排版；来源标签、标题、段落和列表使用清晰的字号与间距。Agent 执行卡片分开显示来源、任务上下文、进度和输出，状态标签按[调用展示规则](sessions.md#agent-调用展示)仅在需要关注时出现，工具调用使用较轻的折叠样式；待响应审批以浅暖色卡片放在输入区上方。代码块和表格在各自区域横向滚动，不撑宽页面，代码复制按钮保留可见；输入区保持紧凑并与正文分隔。

语言切换、审批模式以及 Agent、长期任务、插件和审批表单的单选下拉框使用共享样式；原生控件的外观与验收遵循[协作约定](../../AGENTS.md#代码与组件设计)。

长期任务使用[摘要列表与单项详情](automations.md#列表与详情)，任务状态、执行安排和详情入口分层展示，长正文在列表截断、详情完整呈现；列表和新建表单不同时展开。

窄屏隐藏侧栏，通过顶部按钮展开；输入区工具允许换行，长文本不能导致页面横向溢出。尊重系统减少动态效果的设置，关闭按钮过渡和加载动画。Android/iOS 原生 App 适配屏幕安全区域，首次连接与平台限制见[移动端指南](mobile.md#运行与连接)。

桌面连接弹窗还包含本机局域网访问与开机自启设置，行为和网络访问边界见[桌面设置](configuration.md#桌面设置)。设置加载或保存失败须就地显示错误，失败时不得显示为已保存；加载失败提供重试，保存期间禁用重复操作。

## 客户端访问授权

未授权连接显示授权页，批准后恢复原页面；顶部提供申请处理和已授权客户端管理。已打开且有访问权限的客户端自动检查新申请并弹窗，支持核对后批准、拒绝和稍后处理。申请状态、失败重试、凭据隔离及撤销规则统一见[客户端访问授权](access.md)。

## 系统通知

顶部铃铛打开通知设置，默认关闭；只有用户主动开启时请求系统或浏览器权限，拒绝后提示到对应设置放行并手动检查。开关保存在当前设备的 `omnistream.notifications.enabled`，不改变 Core 的任务、审批和 Slack 监听设置。界面支持中英文。

| 事件 | 通知条件 |
| --- | --- |
| Agent 调用 | 已关联会话的调用从执行状态变为完成、失败或中断；完成仅表示调用结束，验收结论仍以会话结果为准 |
| 长期任务 | 每次执行完成、失败或中断；取消和业务条件不满足的静默跳过不提醒 |
| 待响应 | 新的 Agent 审批、选择、补充输入、插件写入审批及长期任务逐次确认；已处理或失效的请求不再投递 |
| Slack 收件箱 | 当前已启用监听的工作区与本人账号收到新消息；本人发送、重复事件、编辑和删除不生成新提醒，已删除的消息不再投递 |

通知仅展示任务标题或频道 ID，不包含消息正文、执行输出、凭据和审批参数。归档或删除的会话不再投递提醒。点击通知返回对应会话或 Slack 频道；桌面点击取决于系统通知服务是否回传事件，Windows 通知移入操作中心后不保证可点击。桌面接口可用不代表系统允许横幅展示，免打扰和系统通知设置仍可能拦截。

Core 将通知事件与对应结果、审批或消息在同一 SQLite 事务提交，以事件键去重。`POST /notifications/poll` 接收可选 `after` 游标和 `instance`；首次连接或 Core 数据库更换时返回当前游标、实例 ID 和空列表，不补发历史通知。后续每批扫描最多 50 条，按 ID 顺序返回 `items` 和推进后的 `cursor`；过滤掉的事件也推进游标。通知客户端每 3 秒读取统一接口，不逐个查询会话；失败停止轮询，在铃铛显示异常标记，通过设置中的公用失败组件手动重试，保留失败位置。

本地通知成功投递后按 Core 地址与数据库实例保存已发送游标，刷新后不重复提醒；支持 Web Locks 的浏览器串行处理同源多标签页的投递，其他浏览器尽力去重。关闭通知会同步到同源的其他标签页。重新打开页面或重新启用本地通知从当前游标开始。本地模式需要客户端与 Core 保持运行；移动端挂起或被系统回收后不保证继续轮询。浏览器需 HTTPS 或 localhost 和通知权限，已有 PWA Service Worker 时通过它展示，否则使用浏览器 Notification 接口；实际提醒速度仍受后台标签页和操作系统节流影响。

Android 与浏览器另外支持[远程推送](push.md)，连接 Core 并启用系统通知、授予权限后自动注册，无需配对码。注册成功的远程绑定启用后停止本地通知轮询；注册失败保留本地通知。设置显示设备状态、关闭/重新启用入口与失败手动重试，铃铛同步标记远程异常。iOS 原生推送暂缓，保留本地能力。远程配置、关闭语义、后台投递与点击冷启动规则统一见上述文档。

### 通知已读

已读独立于投递游标和审批状态，按当前设备、Core 数据库实例及目标范围保存；会话按会话 ID 区分，Slack 按工作区、本人账号和频道区分。同源浏览器标签页共享已读，其他设备不自动同步。

只有窗口在前台且获得焦点、对应内容加载成功并展示到消息尾部时，才将该内容快照之前的通知标为已读。加载中、查询失败、后台或未聚焦窗口、正在看旧消息，以及弹窗或其他界面遮挡时均不推进；会话含逐次确认卡片时，须等卡片加载成功。仅点击通知或改变路由不算已读。

会话详情和收件箱最新消息页携带在读取内容之前捕获的通知实例、游标及范围；已读仅推进到该快照，不能覆盖之后才产生的事件。阅读旧分页不推进到新消息。本地投递跳过已读事件，但照常推进投递游标；进入对应位置后也清除本机已经展示且属于该快照的通知。已读待响应通知不执行审批、不接受选择，也不代表任务已处理。

已读先保存到设备；远程绑定还会用该设备凭据同步到 Core，使 Core 跳过该设备已读的推送。同步失败保留最新快照，铃铛和通知设置显示异常并提供手动重试；本机已读仍生效，不循环重发失败请求。远程投递和系统清除的能力边界见[远程推送](push.md#已读与通知清除)。

## 多语言设置

GUI 内置中文（`zh-CN`）和英文（`en-US`），首次打开默认使用中文；用户在顶部工具区切换语言后，选择会保存到 `localStorage` 的 `omnistream.locale`，下次打开继续使用。语言切换只影响 GUI 自身的标题、按钮、状态、可访问性标签和页面元信息，不翻译 Core 返回的任务内容、Agent 输出、项目路径或模型名称，也不改变协议值和斜杠命令内部值。

新增界面文案统一维护在 `apps/gui/src/i18n/index.tsx`。添加文案时需同时补充两种语言，并在需要插值的文案中使用 `{name}` 形式；组件不得继续新增散落的用户可见固定文案。

## 数据加载与公用状态

所有数据加载场景优先在对应内容区域使用骨架屏，保持页面布局稳定；独立区域分别展示加载状态，避免局部请求阻塞整个页面。刷新时已有内容仍可用的，可保留内容并在对应区域提示加载进度。

局部骨架屏复用 `StateView.tsx` 的 `LoadingState`，提供可访问的加载状态并尊重减少动态效果设置。查询失败使用 `ErrorState`；操作失败可复用 `MutationError`，由用户手动重试对应操作，重试按钮在请求期间或操作条件不满足时禁用。有副作用的操作重试前须保留核对提示。输入校验失败提供返回修改的操作，不自动重发请求。

空状态和失败状态统一使用 `apps/gui/src/components/StateView.tsx` 提供的 `EmptyState` 和 `ErrorState`；仅单个数值加载失败时使用 `-`，不将整个区域的失败降级为数值占位。两类组件包含 SVG 插图、标题和说明，支持普通与紧凑尺寸；侧栏和弹窗使用紧凑尺寸，内容区域使用普通尺寸。

- 空状态仅在请求成功且无数据时展示，不用空状态替代加载或失败状态。
- 失败状态必须提供对应操作的重试回调；重试期间显示进度文案并禁用按钮，成功后恢复内容。刷新失败时可以保留已有数据并同时提示失败。
- 请求失败后停止自动重试和轮询，等待用户手动重试；切回窗口或网络重连不自动重试。会话详情正常时每 3 秒刷新，连接与会话列表每 15 秒；侧栏不逐个轮询会话设置。
- 两类组件均可传入附加操作，如检查连接地址。插图为装饰，使用空替代文本；失败文案通过 `role="alert"` 提示。
- 空状态与失败插图分别位于 `apps/gui/public/illustrations/empty.svg` 和 `error.svg`，固定比例缩放，不能挤压文案和按钮。
- 表单与执行操作的失败也使用公用失败组件在对应区域展示；重试须由用户手动触发，避免自动重复执行有副作用的请求。

Slack 收件箱的状态和消息每 3 秒刷新，加载失败后停止自动刷新，等待手动重试。Core 的后台 Socket 连接独立于网页，网络断线按[插件市场](plugins.md#持续接收与收件箱)规则重连，不自动重发写入。

验收时检查：成功空数据与失败互斥；重试只请求对应资源且禁用重复点击；恢复后错误消失；桌面和移动端插图、长文案和按钮不溢出。运行 `pnpm --filter @omnistream/gui typecheck` 和 `pnpm --filter @omnistream/gui build` 检查构建。

项目路径补全须区分加载、失败和成功无结果；请求失败不能显示为无匹配项，用户可手动重试当前路径。会话发送失败且仍有待发送消息时，不展示无消息空状态。
