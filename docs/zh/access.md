# 客户端访问授权

客户端访问授权保护整个 Core，独立于会话中的工具、插件写入和长期任务审批。获准客户端具有当前 Core 的完整操作权限，也可以批准、拒绝其他客户端的申请及撤销已有授权；当前不区分用户、项目或只读角色。

## 访问边界

- 监听非回环地址（如 `0.0.0.0:4317`）时，所有业务接口都需要客户端凭据，包括会话流、事件流、设置、文件与推送接口。健康检查和授权申请入口仅开放必要信息。
- 仅监听回环地址时，直接来自本机、Host 与 Origin 都属于回环或本机 Tauri 的请求保留本机访问；转发头或外部 Origin 不取得本机信任。Host、Origin 和转发头不能把远端套接字变成本机客户端。
- 通过反向代理暴露回环 Core 时必须设置 `[access] require_auth = true`，避免代理把远端请求转换成本机连接。公网使用 HTTPS；凭据不放进 URL、更新日志或访问日志。
- 桌面应用自动为自己启动的 Core 注入随机运行期凭据，通过本机 Tauri IPC 使用，开启局域网后本机窗口仍可操作。移动端和普通远程网页不能取得该凭据。

强制授权配置写在 Core 的全局 `config.toml`，位置及 `OMNISTREAM_HOME` 规则见[配置说明](configuration.md)。全局已开启的授权不能由项目配置关闭。

```toml
[access]
require_auth = true
```

## 申请与批准

1. 未授权客户端连接 Core 后显示授权页，填写客户端名称并主动申请。申请端保存本次随机凭据，展示核对码、有效期和等待状态，业务界面在批准前不可用。
2. 正在使用的已授权或受信任的本机客户端每 3 秒检查申请，新申请自动弹窗，展示名称、平台、实际来源地址、Origin 和核对码。用户与申请端核对后明确批准或拒绝；稍后处理可从顶部的客户端授权入口重新打开。客户端关闭或系统暂停后台运行时，需重新打开客户端处理申请；当前授权提醒使用应用内弹窗。
3. 任一客户端完成处理后，其他客户端的弹窗同步移除该申请。申请端确认获准后进入原来准备打开的页面；无需重新填写 Core 地址。
4. 申请 10 分钟过期，可主动取消。拒绝、取消、过期后停止查询，需手动重新申请；网络失败停止轮询并提供手动重试。切换 Core 不会把旧申请或凭据用于新地址。

没有已授权客户端时，在运行 Core 的服务器终端处理第一份申请；使用与 Core 相同的系统用户及 `OMNISTREAM_HOME`：

```bash
omnistream client-auth list
omnistream client-auth approve <request-id> <code>
omnistream client-auth reject <request-id> <code>
omnistream client-auth revoke <client-id>
```

核对码仅帮助用户核实正在批准的设备，不能单独换取访问权限。客户端名和平台是申请方自报信息，不构成可信身份。申请接口限制单来源申请频率和全局待处理数量。

## 凭据与撤销

客户端生成 256 位随机凭据，批准前只可用于查询或取消自身申请；批准后通过 `Authorization: Bearer` 访问业务接口。Core 只持久化凭据哈希，申请列表、设备列表和批准结果不返回凭据，也不通过设备名称或公开 ID 恢复凭据。请求重试必须证明持有本次凭据，不能重用另一客户端的授权。

凭据按完整 Core 地址隔离保存在当前客户端；同一浏览器的标签页共享存储。Core 重启保留已批准客户端，清除客户端存储或丢失凭据后需要重新申请。

客户端授权入口可查看已授权客户端并撤销，包括当前客户端。撤销在服务端立即生效，后续业务请求失败；当前客户端返回授权页。关联的远程推送注册同步停用，后台订阅刷新也必须携带该客户端的有效凭据。已在执行的操作、已排队或已显示的系统通知不保证撤回。

## 验收

检查未授权客户端不能读取会话、设置、推送状态或打开流式接口；申请查询不能读取其他客户端的凭据或状态。覆盖本机信任边界、强制授权、终端首次批准、跨客户端弹窗、批准/拒绝/取消/过期、同时处理、撤销、服务端重启、Core 切换及凭据按地址隔离。远程推送在取得 Core 授权后继续注册与刷新，撤销客户端后停止投递。具体执行记录见[测试指南](testing.md)。
